# AttaLambda 0.6.0 — Generic pure printing

Release preparation is authorized and in progress. The implementation is
merged through [PR #4](https://github.com/kserrec/attalambda/pull/4); publication
and exact archive evidence will be recorded in the
[release ledger](../design/standalone-distribution.md). Linux x86-64 remains
the sole supported public binary target.

## What changes

Version 0.6.0 adds twelve pure functions that return language Strings:
`rat-to-string`, `bool-to-string`, `unit-to-string`, `byte-to-string`,
`char-to-string`, `string-to-string`, `list-to-string`, `option-to-string`,
`result-to-string`, `map-to-string`, `error-to-string`, and `value-to-string`.
The generic renderer handles tagged values recursively, including mixed Lists,
Options, Results, and Maps. Rendering an Error consumes it as printable data.
Other type-specific renderers retain strict typing and incoming-Error behavior.

The thirteenth new function, `print`, renders a value and sends the resulting
String through the existing `stdout` function. It returns stdout's Result and
adds no newline. Calling a pure renderer alone produces no output, and a final
program value is still not automatically printed.

This complete program supplies its own line separators:

```racket
#lang attalambda

(stdout "hello")
(stdout "\n")
(print "hello")
(stdout "\n")
(print -7/3)
(stdout "\n")
(print (some (make-ok (cons 1 (cons TRUE NIL)))))
```

Its exact output, with no newline after the last line, is:

```text
hello
"hello"
-7/3
SOME(OK([1, TRUE]))
```

## Display contract

Rats retain their exact value; fractions are reduced, without decimal rounding.
Strings include quotes and escape control characters, quotes, and backslashes.
Non-ASCII bytes use uppercase two-digit hexadecimal escapes: the String é
displays as `"\xC3\xA9"`, one escape per UTF-8 byte. Map entries keep their stored
order; rendering does not call the Map's equality function or sort entries.
Equivalent Maps may therefore display in different orders. These forms are
human-readable display, not a serialization or parser round-trip promise.

Raw functions are untagged lambdas. Passing one to a renderer or `print`,
directly or inside data, has unspecified behavior; no structured Error is
guaranteed. The unknown-tag placeholder applies only to a well-formed tagged
object with an unknown tag. Complete display also requires finite contents.
See the [API reference](../API.md#value-rendering-and-printing) for all spellings,
strict contracts, and examples.

## Compatibility and purity

Existing programs retain their behavior. `stdout` still accepts only String
and emits its bytes directly; `print` uses the quoted display form for Strings.
Existing Error diagnostic wording and frame ordering are preserved.
The new functions add public names, so programs that already define those names
should check which binding they intend to use under the existing shadowing rules.

All rendering computation expands to variables, unary lambdas, and application.
Printing uses the existing output capability. There is no new host operation,
runtime tag, reflection mechanism, numeric representation, dependency, or
purity exception. The 0.5.0 `rec` rules continue to apply.
Product version 0.6.0 maps to the checked Racket package version 0.6.
