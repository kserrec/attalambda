# AttaLambda 0.5.0 — Pure recursive definitions

Published 2026-09-07 for Linux x86-64:
<https://github.com/kserrec/attalambda/releases/tag/v0.5.0>.
Source verification is recorded in [PLAN.md](../../PLAN.md); exact tag,
archive, checksum, and publication evidence are in the
[release ledger](../design/standalone-distribution.md#attalambda-050--2026-09-07).

## Why 0.5.0

This update repairs a purity enforcement hole and adds public `rec` syntax.
It also rejects recursive `def` programs that 0.4.0 accepted. Advancing the
middle version number makes that new syntax and required migration visible
during the language's 0.x development series. The product version is 0.5.0;
Racket's package metadata uses the checked projection 0.5.

## Purity repair

Previously, a recursive `def` could obtain recursion from Racket's module
bindings even when its body contained only unary lambdas and applications.
Now the public expander rejects direct and indirect cycles among top-level
definitions. The production purity checker independently rejects cycles
among expanded same-module bindings using binding identity.

The rule covers every binding dependency, including aliases and references
that return or pass a function without calling it. Acyclic forward references
remain valid. Function arguments, unary `lambda` parameters, and `let` body
bindings retain their lexical shadowing behavior.

## New syntax and migration

Use `def` for acyclic definitions and `rec` for self recursion. For an
existing self-recursive function, change its declaration keyword:

Before, accepted by 0.4.0:

```racket
(def factorial n =
  (if (eq n 0)
      1
      (mult n (factorial (sub n 1)))))
```

After, runnable with 0.5.0:

```racket
#lang attalambda

(rec factorial n =
  (if (eq n 0)
      1
      (mult n (factorial (sub n 1)))))

(stdout (if (eq (factorial 5) 120) "Recursion works.\n" "Unexpected result.\n"))
```

`rec` accepts zero or more source arguments, curries them into unary lambdas,
and supports partial application. It expands through the existing private
lambda-calculus fixed-point combinator. Its recursive name is bound by a
lambda inside that construction; it is not a recursive module reference.
There is no new runtime primitive or public `fix`/`raw-fix` export.

Mutually dependent top-level definitions remain invalid, including cycles
involving both `def` and `rec`. Replacing every declaration with `rec` does
not make a mutual cycle valid. This release provides no mutual-recursion
syntax; such code requires restructuring into an acyclic lambda construction.

## Diagnostics and compatibility

The launcher returns status 65 for recursive module definitions and gives
a source location with a specific explanation. Direct recursive `def`
reports `recursive def binding is not allowed; use rec for self recursion`.
Indirect cycles receive a distinct cycle explanation. Other source failures
retain their existing diagnostics; raw Racket exception details are not
exposed by these new messages.

The HTTP server example now uses `rec` for its decimal formatter. Core
fixed-point algorithms, lazy evaluation, strict typing, representations,
arithmetic, List operations, and the ten host capabilities are behaviorally
unchanged. No dependency or runtime capability was added. Linux x86-64
remains the sole supported public binary target; macOS and Windows remain
internal portability checks.
