## What changed

`attalambda --check FILE.attl` checks a complete source file without running it.
No annotations or new source syntax are required. The report includes exact
definition/expression coverage, verified inferred signatures, source locations,
and reasons for incomplete checking. Checking performs no program input/output,
file/network/exit effects, or shell-history access.

The checker infers finite function/container types, reusable rank-1 polymorphic
definitions and source lets, acyclic forward definitions, and monomorphic
recursive self calls. Built-in contracts are explicitly audited: 106 complete,
23 deliberately partial, with no pending entries. Ordinary execution and the
runtime type checks continue to work as before.

| Status | Meaning |

## Scope and compatibility

Checking is optional. The interactive shell, source syntax, runtime type tags,
exact rational representation, strict wrappers, lazy evaluation, pure unary
lambda computation, and sole host boundary are preserved. A static FAIL does
not mean the program must crash when executed; the checker uses homogeneous
List and branch-result types.

The first version has no variant, nonempty or numeric-range refinements. For
example, `unwrap-ok` remains partial behind `is-ok`, and `head` remains partial
on a visibly nonempty List. Raw host protocols, unsupported data domains and
recursive types retain explicit gaps. FULL PASS relies on trusted built-in,
recursive-lowering and host/codec contracts; it does not prove termination,
successful external operations or absence of deliberate Error/Result Err values.

See the [checking reference](../API.md#optional-static-checking),
[contract inventory](../static-checking-contracts.md), and
[measured five-example corpus](../static-checking-corpus.md). Linux x86-64
remains the only supported binary download.
