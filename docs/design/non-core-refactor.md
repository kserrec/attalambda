# Non-core simplification specification

Approved by Kyle on 2026-09-05. Execution has started.
The canonical copy is `docs/design/non-core-refactor.md`; `PLAN.md` alone
orders execution. This replaces the earlier refactor proposals.

## Required result

Less code, less indirection, less maintenance, and less reading to understand
a task. Preserve functionality and useful safeguards. Improve the existing
implementation through deletion, consolidation, and direct code.

Every proposed edit must name existing complexity it removes. Count complete
call paths, including helpers, callers, tests, and checker changes. Moving
code, compressing formatting, stripping explanations, or hiding branches
behind an abstraction does not qualify. Necessary checks and platform mappings
stay even when they are long. Keep working code when no smaller, clearer,
equally correct version is demonstrated.

Completion requires a net reduction in non-pure implementation code and in
maintained code overall, including tests/tooling. Report documentation
separately; deleting prose cannot satisfy the code goal. Verify actual removed
functions/branches alongside physical source lines. No permanent metrics
framework is needed. If this goal cannot be met safely, report that fact
instead of expanding the project or manufacturing a reduction.

Use existing modules and direct local functions. Do not add a request-type
hierarchy, runtime decoder module, generic dispatcher/schema, prelude, literal
module, universal codec, checker framework, dependency, reflection, generated
native code, or convenience abstraction. A shared helper must remove actual
duplication and reduce the combined code and effort needed to follow it.

## What is protected

The three documents in `docs/specifications/` remain normative, with their
existing precedence. The protected center is **all pure untyped lambda
computation, wherever it occurs**, not just files under `core/`. This includes
pure effects/protocol/request construction, validation, HTTP parsing and server
decisions, and terms generated by macros. After expansion, computation still
contains only variables, unary lambdas, and application. Native scaffolding
must never decide an object-language result.

Keep all representations, public names/exports, generalized runtime typing,
Error propagation and exact remaining-argument absorption, Result semantics,
partial application, laziness, effect order, and literal encodings. Rat stays
the only public number; private binary Nat/Int, canonical zero, byte ranges,
proper Lists, and the existing NIL/sentinel admission rule remain intact.
No pure algorithm, List reconstruction, new completion convention, or public
interface change belongs to this refactor.

`runtime/host.rkt` remains the sole privileged producer, resource owner, and
production codec importer. Keep `runtime/codec.rkt` deterministic, effect-free,
without mutation/registries, and outside the pure dependency graph. The
language facade re-exports/injects the same host once. Readers remain observers
without effects, state, upward imports, or production dependents. Tests/tooling
remain classified support code outside production dependencies.

No new effects, authority exceptions, syntax, types, optimizers, concurrency,
protocols, security/sandbox claims, platform targets, or dependencies.
Distribution/CI scripts are outside cleanup scope. Existing tests still verify
packaging; do not add another build or acceptance system.

## Preserve the host and codec contracts

Keep one understandable route inside the existing modules:
request -> native dispatch/decoding in host -> approved performer -> codec
conversion -> pure Result or contract Error. No parallel old/new dispatcher.

| Operation | Native decoded arguments | Successful pure result |
| --- | --- | --- |
| stdout | String bytes | Ok UNIT after write/flush |
| read-file | path String bytes | Ok (List Byte) |
| write-file | path String bytes, List Byte bytes | Ok UNIT after replacement |
| tcp-connect | hostname bytes, integer port 1..65535 | Ok handle Rat |
| tcp-listen | interface bytes, integer port 0..65535, backlog 1..65535 | Ok List of handle and bound-port Rats |
| tcp-accept | positive integer listener handle | Ok connection-handle Rat |
| tcp-read | positive integer connection handle, maximum 1..65536 | Ok (List Byte), empty at EOF |
| tcp-write | positive integer connection handle, payload bytes | Ok UNIT after complete write |
| tcp-close | positive integer handle | Ok UNIT after removal and cleanup |

All native counts/handles above are decoded from whole Rat arguments.
Preserve left-to-right rejection and forcing precedence, arity/type/range
checks, pure wrapper validation, unknown-operation details, Error frames,
and bare contract Error versus expected external Result Err.

Keep these fifteen external codes and their existing POSIX/Windows mappings:
`not-found`, `permission-denied`, `invalid-path`, `invalid-text`,
`invalid-handle`, `wrong-handle-kind`, `address-in-use`,
`connection-refused`, `connection-reset`, `broken-pipe`,
`network-unreachable`, `name-resolution-failed`, `resource-exhausted`,
`timed-out`, `io-failure`. Keep request reasons `unknown-operation`,
`wrong-arity`, `wrong-type`, `out-of-range`, existing kinds/detail fields,
and sanitized failures. No exception text, errno, native path/hostname, or
Racket object enters returned error data.

Keep UTF-8 path/name interpretation in host and payloads byte-exact. Preserve
ephemeral ports/empty interfaces, full and empty writes, EOF, monotonically
allocated handles, stale/wrong-kind rejection, remove-before-close ordering,
attempted cleanup of both ports, and cleanup when registration/conversion fails.
Keep actual resource helpers; reduce repeated forwarding, not lifecycle logic.

Preserve the concrete two-way codec API and its `codec-failure` results:
List, String/bytes, List Byte/bytes, exact Rat, and Ok/Err/Unit constructors.
Retain all 256 Byte/Char values, empty/embedded-zero bytes, immutable decoded
bytes, input-copy guarantees, normalized magnitudes, reduced positive
denominators, the one positive zero, malformed-value rejection, and cycle
detection. Neither NIL identity nor numeric normalization is redesigned.
No ordinary language arithmetic or I/O moves into conversion.

## Preserve frontend, runner, and checks

Mechanical emission may become smaller, but expanded pure behavior, lexical
context, shadowing, canonical names, strict `if`/`cons`, the public prelude,
and one-time host injection stay the same. Definitions and unused branches or
payloads remain lazy; preceding effects occur once in order. Returned ordinary,
indirect, and partially applied functions are never called to classify them.

Keep the present source-path policy, including source-symlink/dotenv refusal
and accepted parent links. Remove custom path/preflight logic only with proof
that ordinary Racket handling preserves that policy and its diagnostics.
Keep `attalambda FILE.attl`, help/version, lowercase extension, exact header,
UTF-8, regular-file validation, one source load, sanitized diagnostics, and
statuses 0/64/65/66/70. Completed Error/Err values remain status 0 without final
value printing. The sole planned wording correction changes the obsolete
Nat-only literal diagnostic to the existing exact Rat/String contract.

Maintain the existing expanded purity and closed boundary checks. Remove an
incidental private-body/name assertion only after identifying its protected
promise and demonstrating equivalent remaining protection. A smaller blacklist
cannot replace closed restrictions on implicit/renamed/phase-specific native
capabilities. Keep sole host/codec authority, public exports, import directions,
reader restrictions, safe discovery, and rejection of unknown source locations.
Necessary private locks may remain; do not build a new analysis engine to
eliminate them. Minimum exact-rule updates for the approved local edits are
allowed, with affected behavioral and adversarial tests in the same Step.

## Verification, documentation, and stopping

Use existing tests, fixtures, and distribution scripts. Add or repair a test
only for a named real failure or protection lost by a change. Preserve test
intent, sole coverage, isolation, deadlines, and cleanup. Deleting superseded
assertions is authorized only after equivalent protection is demonstrated.
A review may find nothing. Bugs need a reproduction or concrete complete trace;
fix causes serially and check related cases. Fresh review of bug/test repairs
and one final independent review are required; no speculative hardening or
repeated skill chain. Follow the repository's diagnosis and cold-review rules.

Each Step includes focused verification and diff review. Production changes
also run both checkers; each Phase commit requires the full suite. Reuse a
current passing run when its inputs are unchanged. Test hostile mutations only
in isolated fixtures, file effects in temporary directories, and network
effects on ephemeral loopback ports. Never inspect dotenv contents, including
synthetic ones; explicitly exclude `.env`, `*.env`, `.env.*`, `*.env.*`
from every recursive listing/search/bulk read and diff. No Graphify.

Permanent docs should give direct entry points and explain actual roles.
A reader should understand native request handling from host/codec alone and
follow only the relevant functions. Keep unique legal/release evidence and
the deferred HTTP-parser finding once; remove duplicated process narration.
Do not delete normative specs or replace working history with invented facts.

Final Linux acceptance uses the existing pinned Racket CS 9.3 builder and
independent consumer on a clean recorded implementation commit. Preserve
artifact names/formats, version projection, checksums, safe staging/extraction,
offline runtime, registry/checkout isolation, permissions, cleanup, relocation,
legal notices, Linux-only public support, and unchanged macOS/Windows tooling.
Record the exact tested revision/checksum. A later docs-only closing commit is
separate; changes to shipped/build inputs require repeated acceptance.

Work stays on `refactor/non-core-simplification`. Execute the thirteen Steps
serially and commit/push verified
Phases to the verified destination without routine approval requests. Real
verification/access or normative blockers require an honest stop, not new scope.
No paid usage, system changes, publication, signing, or artifact-policy change.

Completion requires preserved functionality/authority, passing checks and
distribution acceptance, actual code reduction, and demonstrably easier reading.
Then stop, even after generic `next` or another skill invocation. No PR until
Kyle reviews the completed branch and explicitly authorizes it; no merge,
release, deferred feature, or further cleanup follows automatically.
